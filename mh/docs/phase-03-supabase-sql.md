# Phase 3 - Supabase SQL

## What This Phase Builds

Phase 3 creates the database objects needed by the running app:

- Application tables.
- Primary keys and foreign keys.
- Constraints.
- Indexes.
- `updated_at` triggers.
- Profile auto-creation trigger after Supabase Auth signup.
- RPC functions for leaderboard, member dashboard, and challenge progress.

SQL file:

```text
sql/phase-03-schema.sql
```

Run this file in Supabase SQL Editor before running Phase 4.

- `public.profiles`
- `public.running_records`
- `public.challenges`
- `public.challenge_members`

Helper functions:

- `public.set_updated_at()`
- `public.is_admin()`
- `public.is_active_member()`

RPC functions:

- `public.get_leaderboard(range_key text)`
- `public.get_member_dashboard_summary()`
- `public.get_challenge_progress(challenge_id_input uuid)`

## Important Design Notes

`profiles.id` references `auth.users(id)` so each authenticated user has exactly one application profile.

`running_records.pace` is generated by PostgreSQL:

```text
duration_minutes / distance_km
```

Leaderboard and dashboard calculations use approved records only.

The browser should call RPC functions for totals instead of downloading all records and calculating in JavaScript.

## Testing Steps

1. Open Supabase SQL Editor.
2. Paste and run `sql/phase-03-schema.sql`.
3. Confirm tables exist in Table Editor.
4. Register a test user using Supabase Auth or the future frontend.
5. Confirm a matching row is created in `profiles`.
6. Insert a sample running record as that user after Phase 4 policies are applied.

## Notes Before Phase 4

This phase creates security helper functions, but it does not enable RLS policies. Run Phase 4 immediately after Phase 3 before using the app with real users.
