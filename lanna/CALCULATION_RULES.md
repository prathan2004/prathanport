# หลักการคำนวณวันดีวันเสียล้านนา

วันที่ศึกษา: 22 ตุลาคม 2569 (Asia/Bangkok)

สถานะ: Phase 1 — อนุมัติกฎวันเสียตามหลักฐานและเลือก S2 เป็นแหล่งหลักของฟ้าตี๋แส่งแล้ว ส่วนระบบเดือนและรายละเอียดการถอดสูตรจากต้นฉบับยังรอยืนยัน ยังไม่มีการพัฒนาเว็บไซต์หรือเปิดใช้สูตร

## 1. ผลการศึกษาและข้อเสนอ

ผู้ว่าจ้างอนุมัติให้ใช้กฎวันเสียตามหลักฐานที่ค้นพบแทนตารางเดิม และเลือกงานวิจัยในคลังมหาวิทยาลัยเชียงใหม่ บทที่ 3 (S2) เป็นแหล่งหลักของฟ้าตี๋แส่งแล้ว การเลือกแหล่งอ้างอิงไม่ใช่การรับรองข้อมูลปฏิทินรายวันหรือความถูกต้องของข้อความที่ถอดจาก PDF ข้อเสนอสำหรับเวอร์ชันแรกคือใช้ปฏิทินรายวันที่มีหลักฐานกำกับ จำกัดช่วงวันที่ตามข้อมูลที่ตรวจแล้ว และแสดงสถานะรอการยืนยันเมื่อข้อมูลไม่ครบ ห้ามคาดคะเนเดือนหรือขยายข้อมูลออกนอกช่วงเอง

## 2. แหล่งอ้างอิงและระดับหลักฐาน

### S1 — ปฏิทินล้านนา พ.ศ.2569 โหรา–ปากเล้ม

ผู้จัดทำ: ศักดิ์นรินทร์ ชาวงิ้ว ศูนย์วัฒนธรรมศึกษา มหาวิทยาลัยเทคโนโลยีราชมงคลล้านนา

[ต้นฉบับ PDF](https://e-cms.rmutl.ac.th/assets/upload/files/2025/11/ปฏิทินล้านนา_โหราปากเล้ม_ศวธ_1388_ขวาง.pdf)

เป็นเอกสารจากผู้จัดทำโดยตรง เหมาะเป็นหลักฐานรายวัน เลขหน้าด้านล่างนับจากหน้าแรกของไฟล์เป็นหน้า 1 ตรวจข้อความคำนำและตารางตุลาคมแล้ว แต่ยังไม่ได้ตรวจตารางทั้งเล่มทีละวัน ภาพหน้า PDF ผ่านเครื่องมือเว็บแสดงผลไม่สำเร็จ จึงต้องตรวจภาพก่อนรับรองค่ารายแถว

### S2 — งานวิจัยในคลังมหาวิทยาลัยเชียงใหม่ บทที่ 3 ประเภทของเนื้อหาในปักขทืนล้านนา

[บทที่ 3](https://archive.lib.cmu.ac.th/full/T/2549/lanna0449st_ch3.pdf)

เป็นงานศึกษาที่รวบรวมเอกสารโบราณ ผู้ว่าจ้างเลือกให้เป็นแหล่งหลักสำหรับสูตรฟ้าตี๋แส่งของโครงการ ไม่ถือว่าแทนต้นฉบับทุกสำนักได้ หัวข้อ 3.2.5.32 อยู่หน้าเอกสาร 133–134 (หน้าไฟล์ 92–93) ชื่อผู้วิจัยและข้อมูลบรรณานุกรมเต็มยังต้องตรวจจากส่วนต้นของวิทยานิพนธ์

[วันดีวันเสียที่ปรากฏในวรรณกรรมล้านนา](https://www.teeneelanna.com/moojoomhao/home/space.php?do=blog&id=263&uid=1)

### S4 — คำอธิบายระบบของเว็บไซต์มรดกล้านนา

[เกี่ยวกับปฏิทิน](https://www.moradoklanna.com/calendar/about)

เป็นคำอธิบายจากผู้พัฒนาระบบเอง กล่าวถึงทางเลือกการนับเดือนซ้ำในการหาฟ้าตี๋แส่ง ใช้ระบุความเสี่ยงเรื่องวิธีนับ ไม่ถือคำกล่าวว่าตรวจตรงกับปั๋กขะตืนเป็นการตรวจรับของโครงการนี้

## 3. วันเสีย: ใช้กฎตามหลักฐานที่ค้นพบ (อนุมัติแล้ว)

คำยืนยันจากผู้ว่าจ้าง: “วันเสีย: ใช้หลักฐานที่ค้นมา” ให้ใช้คอลัมน์ขวาของตารางต่อไปนี้เป็นกฎของโครงการ คอลัมน์คำขอเดิมเก็บไว้เพื่อแสดงที่มาของการเปลี่ยนแปลง

| เดือน | ตามคำขอเดิม | กฎตามหลักฐานที่อนุมัติให้ใช้ |
|---|---|---|
| 1, 5, 9 | อาทิตย์ จันทร์ | อาทิตย์ จันทร์ |
| 2, 6, 10 | อังคาร | อังคาร |
| 3, 7, 11 | พุธ ศุกร์ | พฤหัสบดี เสาร์ |
| 4, 8, 12 | พฤหัสบดี เสาร์ | พุธ ศุกร์ |

ตัวอย่างจากข้อความตาราง S1 หน้าไฟล์ 5: วันที่ 2 มกราคม 2569 เป็นวันศุกร์ เดือนปากเล้ม 4 มีเครื่องหมายเสีย ขณะที่โหราเดือน 3 แสดงเสียในวันเสาร์ที่ 3 มกราคม จึงไม่สอดคล้องกับสองแถวท้ายของคำขอ ผู้ว่าจ้างเลือกใช้แนวทางตามหลักฐานแล้ว แต่ยังต้องตรวจภาพก่อนรับรองค่ารายแถวเป็นข้อมูลอ้างอิงทดสอบ

กฎที่อนุมัติ: `วันเสีย = วันในสัปดาห์อยู่ในชุดวันเสียของเดือนและแนวทางที่เลือก` แยก ruleSetId และ calendarSystem ชัดเจน ผลที่ไม่เข้ากฎให้ใช้ข้อความ “ไม่ตรงกับวันเสียตามเกณฑ์นี้” ห้ามสรุปเป็นวันมงคล การนำไปตรวจวันที่สากลยังต้องมีเดือนล้านนาที่ตรวจยืนยันแล้ว

## 4. เดือนล้านนา ปีใหม่ และอธิกมาส

S1 คำนำหน้าไฟล์ 3 แยกปากเล้มเชียงใหม่กับโหรา และระบุว่าการวางอธิกมาสอาจต่างในบางพื้นที่ จึงต้องระบุระบบเดือนก่อนเปรียบเทียบ ข้อเสนอคือปากเล้มเชียงใหม่เป็นค่าเริ่มต้น พร้อมชื่อระบบที่มองเห็นได้

ไม่ใช้เดือนสากลแทนเดือนล้านนา ไม่ใช้การบวกเลขเดือนภาคกลางเป็นตัวแปลงวันที่ทั่วไป ปีจุลศักราชและชื่อปีต้องแยกจากการวนเลขเดือน ตารางเดือนซ้ำต้องเก็บลำดับครั้งไว้ และวันขึ้นปีใหม่ต้องมาจากหลักฐานของปีนั้น

ข้อเสนอข้อมูลรายวัน: `isoDate`, `calendarSystem`, `lannaMonth`, `monthOccurrence` (ปกติ/ก่อน/หลัง), `phase`, `lunarDay`, `chulaSakarat`, `sourceId`, `sourcePage`, `verificationStatus` และข้อมูลผู้ตรวจ ใช้เฉพาะรายการที่ตรวจรับแล้ว หากไม่มีรายการ ให้คืน “ยังไม่สามารถยืนยันเดือนล้านนา”

## 5. ฟ้าตี๋แส่ง: ใช้งานวิจัย มช. บทที่ 3 เป็นแหล่งหลัก (อนุมัติแล้ว)

คำยืนยันจากผู้ว่าจ้าง: “ฟ้าตี๋แส่ง ใช้ งานวิจัยในคลังมหาวิทยาลัยเชียงใหม่ บทที่ 3 ประเภทของเนื้อหาในปักขทืนล้านนา” จึงเลือก S2 เป็นแหล่งหลัก ไม่ใช้สูตรจาก S3 แทน และไม่ต้องขออนุมัติการเลือกแหล่งนี้ซ้ำ

กำหนด C = จุลศักราชของวันนั้น, K = เกณฑ์เดือนตามตำราที่เลือก, T = ติถีวันตามนิยามตำรา และ mod เป็นเศษไม่ติดลบ

| หลักฐาน | รูปคณิตศาสตร์ที่ถอดจากข้อความ | สถานะ |
|---|---|---|
| S2 หน้าเอกสาร 133 | `mod(4 × ((C mod 108) + K + T) − 7, 9)` | แหล่งหลักที่ผู้ว่าจ้างเลือก ข้อความที่ดึงได้ระบุตัวคูณ 4 ต้องตรวจภาพต้นฉบับก่อนเปิดใช้ |
| S3 หัวข้อสูตรการคำนวณ | `mod(5 × ((C mod 108) + K + T) − 7, 9)` | เก็บเป็นข้อมูลเปรียบเทียบเท่านั้น ไม่ใช่สูตรของโครงการ |

ทั้งสองข้อความจัดเศษ 2, 4, 5, 6 อยู่ในกลุ่มดีตามความเชื่อ แต่ความตรงกันของคำแปลเศษไม่ยืนยันความถูกต้องของการถอดสูตร ให้ยึด S2 และตรวจตัวคูณกับภาพต้นฉบับ ห้ามแก้เป็น 5 ตาม S3 เอง ห้ามนำเศษที่คำนวณเองมาใช้เป็น expected value เพื่อรับรองตัวเอง

ยังต้องตรวจตาราง K ครบ 12 เดือน นิยาม T ในข้างแรม การเปลี่ยน C และวิธีนับเดือนซ้ำจาก S2 หาก S2 ไม่ระบุกรณีใดเพียงพอ ให้กรณีนั้นรอการยืนยัน ไม่เติมกฎจาก S3 หรือ S4 เอง ข้อมูลความต่างเรื่องเดือนแทรกใน S4 เป็นเพียงประเด็นตรวจสอบ ห้ามแทน T ด้วยวันที่สากล และยังไม่ถือว่าข้อความที่ต่างกันเป็นคนละสำนักจนกว่าจะตรวจต้นฉบับได้

ก่อนเปิดใช้: ตรวจภาพหน้าเอกสาร 133–134 ถอดตัวแปรและขั้นตอนตาม S2 ให้ครบ และตรวจตัวอย่างอ้างอิงที่เป็นอิสระจากโค้ด ระหว่างที่ข้อมูลยังไม่ครบให้ผลโมดูลเป็น “รอการยืนยันหลักการคำนวณ” ไม่แสดงเศษหรือคำตัดสินดี/เสีย ไม่มีการเปิดใช้สูตรใดใน Phase 1

## 6. กรณีศึกษา 19 ตุลาคม 2569

วันที่ ISO: 2026-10-19; พ.ศ.2569 = ค.ศ.2026 + 543; วันจันทร์ตามปฏิทินสากล

สถานะเดือนล้านนา เครื่องหมายวันเสีย และฟ้าตี๋แส่ง: รอตรวจภาพแถววันที่ 19 ใน S1 หน้าไฟล์ 24 และทวนกับปั๋กขะตืนอีกฉบับ ยังไม่รับรองค่าทางล้านนา และยังไม่สรุปผลทั้งสองวิธี

## 7. แผนทดสอบหลังอนุมัติ

แยกชุดทดสอบกฎที่อนุมัติจากชุดข้อมูลอ้างอิงรายวัน ทุก expected value ทางวัฒนธรรมต้องผูก source/page/system ห้ามแสดงการทดสอบที่ยังไม่ยืนยันเป็น passed

| กลุ่ม | กรณีที่ต้องตรวจ |
|---|---|
| 12 เดือน | แต่ละเดือนทดสอบวันเสียและวันที่ไม่เสีย รวมอย่างน้อย 24 กรณีตาม rule set ที่อนุมัติ |
| กรณีศึกษา | 2026-10-19 พร้อมหลักฐานแถวรายวัน |
| ปีสากล | 2024-02-29, 2023-02-29 (ต้องปฏิเสธ), 2026-12-31, 2027-01-01 |
| ขอบเขตล้านนา | ก่อน/หลังเปลี่ยนเดือน ก่อน/หลังเปลี่ยนปี และเดือนซ้ำก่อน/หลัง เลือกวันที่จากหลักฐาน |
| ฟ้าตี๋แส่ง | ตัวอย่างอ้างอิงครอบคลุมเศษ 0–8 และข้างขึ้น/แรม รวมกรณีเดือนแทรก |
| ข้อมูลขาด | นอกช่วงข้อมูล รายการไม่ตรวจรับ ขาดเดือน/แหล่งอ้างอิง ต้องไม่คำนวณต่อ |
| สรุป | สอดคล้อง ขัดแย้ง คำนวณได้วิธีเดียว และคำนวณไม่ได้ทั้งคู่ |
| เวลา | ทดสอบก่อน/หลังเที่ยงคืนกรุงเทพฯ เมื่อเครื่องผู้ใช้มีเขตเวลาอื่น |

ตารางนี้เป็นแผน ยังไม่มี unit tests หรือ production build ใน Phase 1

## 8. ประเด็นขออนุมัติก่อน Phase 2–3

1. ใช้ปากเล้มเชียงใหม่เป็นระบบหลัก และจำกัดช่วงวันที่ตามข้อมูลรายวันที่ตรวจแล้วหรือไม่? เสนอเริ่มปี 2569 ก่อน ข้อมูลที่ยังไม่ตรวจใช้สถานะไม่ยืนยัน
2. **อนุมัติแล้ว:** ใช้ตารางวันเสียตามหลักฐานในหัวข้อ 3 แทนตารางเดิม ไม่ต้องขออนุมัติการเลือกกฎนี้ซ้ำ ส่วนการตรวจภาพข้อมูลรายวันยังต้องดำเนินการ
3. **อนุมัติแล้ว:** ใช้ S2 งานวิจัยในคลังมหาวิทยาลัยเชียงใหม่ บทที่ 3 เป็นแหล่งหลักของฟ้าตี๋แส่ง ไม่ต้องขออนุมัติการเลือกแหล่งนี้ซ้ำ ต้องตรวจภาพต้นฉบับ ตัวแปร และตัวอย่างให้ครบก่อนเปิดใช้ตามหัวข้อ 5

เหตุที่หยุด: คำขอกำหนดให้รายงาน Phase 1 และขออนุมัติสูตร/วิธีแปลงเดือนก่อนพัฒนาขั้นถัดไป ไม่ใช่การขออนุญาต deploy และยังไม่มีการเผยแพร่เว็บไซต์
